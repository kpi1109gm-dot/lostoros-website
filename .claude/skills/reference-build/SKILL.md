# reference-build: 参照 → 分解 → 実装

参照サイトを取得・解析し、デザインの本質を分解メモとして文書化してから、
独自デザインとして実装する一貫フロー。デザインの丸コピーは行わない（著作権）。
「なぜそう見えるか」を抽出し、このプロジェクトの文脈に翻訳する。

## STEP 1 — 参照（取得）

1. `scripts/capture.js` を使い、参照URLのスクリーンショットと構造情報を取得する:
   ```bash
   cd <scratchpad> && npm i playwright --no-audit --no-fund
   node <skill-dir>/scripts/capture.js <URL> <出力ディレクトリ>
   ```
   - 複数スクロール位置のスクリーンショット、モバイル表示、
     使用フォント・色・見出し階層・読み込みスクリプトのJSONが得られる
2. この環境固有の注意:
   - Chromium実行パスは `/opt/pw-browsers/chromium`（`playwright install` は不要）
   - プロキシ環境ではTLS 1.3拡張が弾かれるため
     `--ssl-version-max=tls1.2` フラグと `proxy: { server: process.env.HTTPS_PROXY }` が必須
   - 外部サイトが403で拒否される場合は環境のネットワークポリシーを確認
     （Trusted → Full に変更が必要。docs/project-brief.md の環境メモ参照）
3. スクリーンショットをReadツールで実際に見て確認する。JSONだけで判断しない。

## STEP 2 — 分解（文書化）

`docs/design-analysis.md` に以下の観点で分解メモを書く（既存ファイルがあれば追記）:

- **技術スタック**: 何で作られているか（読み込みスクリプトから判定: GSAP, Three.js, Webflow等）
- **タイポグラフィ**: フォントの種類・数・使い分け・サイズの振れ幅（最小と最大）
- **配色**: 使用色を全て列挙し、基調色とアクセント色の比率を見る（色数の少なさに注目）
- **レイアウト構造**: セクション分割、グリッド、余白、罫線・番号などの編集的装置
- **モーション**: スクロール連動・マーキー・パララックス・ホバー等の種類と量
- **本質の言語化**: 「なぜスタイリッシュ/シンプル/先進的に見えるか」を3〜5行で言い切る

最後に **翻訳表**（参照要素 → このプロジェクトでの置換）を必ず作る。
ここが丸コピーと独自デザインの分岐点になる。

## STEP 3 — 実装

1. 翻訳表に従い HTML/CSS/JS を書く。このプロジェクトの規約:
   - 静的サイト（index.html / css/style.css / js/main.js）、ビルドツールなし
   - フォントはGoogle Fonts（ブランドフォント: Goldman。和文: Noto Sans JP、英ラベル: Space Mono）
   - アニメーションはvanilla JS（IntersectionObserver + rAF）とCSSで実装。外部ライブラリは避ける
   - `prefers-reduced-motion` を尊重する
   - 未提供素材（写真・ロゴ等）はプレースホルダーにして `<!-- TODO: -->` コメントを残す
2. **必ず自分の目で確認する**:
   ```bash
   python3 -m http.server 8901 &
   node <skill-dir>/scripts/capture.js http://127.0.0.1:8901/ <出力ディレクトリ>
   ```
   スクリーンショットをReadで見て、切れ・重なり・色化け・レスポンシブ崩れを修正。
   直したら再度撮影。問題がなくなるまで繰り返す。
3. 完成スクリーンショットをSendUserFileでユーザーに送り、フィードバックを待つ。
