# PHP脆弱性（PHP2Shell）の影響確認と、お問い合わせAPIの安全対策

日付: 2026-10-22 / 実装: Claude Code / 依頼者: 池田海

## 経緯

2026-10-21に公表されたPHPの重大な脆弱性（CVE-2026-109618 / CVE-2026-109619、
通称 PHP2Shell。CVSS 9.2、認証なしで遠隔からコード実行）について、
池田さんから「解説と、自社サイトの検査」を至急で依頼された。

## 結論：PHP2Shellの影響はない

**このサイトはPHPを一切使っていない。**

| 部分 | 仕組み | 確認内容 |
|---|---|---|
| lostoros.net | GitHub Pages（静的配信） | `server: GitHub.com`。`/index.php`・`/wp-login.php`・`/info.php` はすべて404 |
| フォーム受信API | Render上のNode.js（Express） | `/index.php` は404 |
| リポジトリ | — | `.php`・`composer.*`・`.htaccess`・`php.ini` なし |

Square（決済）・Wix（ドメイン）は各社管理のサービスで、こちらで対応することはない。

## あわせて見つかった問題（PHPとは無関係）

`npm audit` で受信APIの部品に「重大1・高1・中3」の警告。
**警告の数ではなく、実際に悪用できるかを1件ずつコードで確かめた。**

| 部品 | 判定 | 実際 |
|---|---|---|
| proxy-addr | 重大 | **発動しない**。サブネット文字列で信頼範囲を指定した場合の問題。当サーバーは `trust proxy` を数値の `1` で指定しており、Express は数値のとき `function(a, i){ return i < val }` を使うため proxy-addr の該当処理を通らない（`node_modules/express/lib/utils.js` で確認） |
| qs ×2 | 中 | **発動しない**。`comma: true`、または parse→stringify の往復が必要。当サーバーはどちらも使っていない |
| nodemailer | 高・中 多数 | 大半は未使用の機能（OAuth2・raw・添付・許可リスト等）。ただし**フォーム入力を返信先に渡す経路**が該当しうる |

### 実際に再現した問題（修正前）

テスト用のSMTPサーバーを手元に立て、細工したリクエストを送って確認した。

| テスト | 修正前 | 修正後 |
|---|---|---|
| お名前に `Taro", evil@attacker.example, "x` | **返信先に攻撃者のアドレスが追加された** | 記号を除去。返信先は本人の1件のみ |
| メール欄に `x>,<evil.example@attacker.example` | **返信先が攻撃者にすり替わった** | 400で拒否 |
| 2万文字のメールアドレス | 受け付けて送信 | 400で拒否 |
| 1万文字の種別 | 1万文字の件名で送信 | 400で拒否 |
| お名前に改行＋`Bcc:` | （改行は送信部品がエンコード） | 改行を空白に置換 |
| メール欄にカンマで2件目 | — | 400で拒否 |
| 日本語の名前・`+`付きアドレス・改行のある本文 | 正常 | **正常（変化なし）** |

返信先の問題は、受信者（千田さん・池田さん）が「返信」を押すと第三者に届くというもの。
**原因は部品ではなく、自前のコードで返信先を文字列連結で組み立てていたこと。**

## 変更内容

| 内容 | ファイル |
|---|---|
| 返信先を文字列ではなく `{ name, address }` で渡す（送信部品が入力を解析し直さない） | server/index.js |
| メールアドレスを254文字までに制限し、宛先の区切りになる記号を含むものを拒否 | server/index.js |
| 名前・会社名・種別の改行や制御文字を空白に置換。表示名から `" < > ( ) [ ] \ , ; : @` を除去 | server/index.js |
| 種別に100文字の上限を追加（これまで上限なし） | server/index.js |
| `X-Powered-By: Express` を出さない | server/index.js |
| 互換性が保たれる範囲で部品を更新（proxy-addr 2.0.8 / qs 6.16.1 / express 4.22.3 / body-parser 1.20.8） | server/package-lock.json |
| 実行環境を Node.js 22 以上に指定（Node.js 20 は2026年4月でサポート終了） | server/package.json |

## 残した課題

- **nodemailer 6.10.1 → 10系への更新**。高の警告が1件残る（`npm audit fix --force` が必要な大きな版の更新）。
  返信先を構造化して渡すようにしたため、フォーム入力から該当処理に届く経路はふさいだ。
  ただし根本対応として、**本番でのテスト送信ができる日に**更新すること
- フロント側（js/main.js）のメール形式チェックは従来の緩いまま。
  サーバー側で拒否されるので安全上の問題はないが、まれに「送信に失敗しました」と表示される

## 検証

- 修正前後で同じ9件のテストを実行（上表）。修正後の起動エラーなし
- Resend方式は外部に送らず、偽のAPIで送信内容を確認：`reply_to = "山田 太郎 x" <taro@example.com>`
- ローカルの Node.js は v22.22.0
